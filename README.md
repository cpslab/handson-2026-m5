# handson-2026-m5

研究室の新3年生向けハンズオン「**PlatformIO × M5Stack CoreS3 マイコンコーディング回**」の教材・デモ一式です。
複数の講師で開発しています。作業を始める前にこの README を一読してください。

---

## ハンズオンの概要

| 項目 | 内容 |
|---|---|
| 対象 | 研究室に新しく入る3年生 **10人**（マイコン初心者を想定） |
| 時間 | **約200分** |
| 機材 | 各自のPC（PlatformIO は事前インストール済み）、M5Stack **CoreS3**、外付けセンサー（**使用必須**） |
| 最終ゴール | **息を吹き込むと風船が膨らむゲーム**を全員で遊ぶ |

### 風船ゲームのイメージ

1. 各自がチューブに息を吹き込む
2. 大画面（プロジェクター）上で自分の風船が膨らむ
3. 一定以上膨らむと割れる
4. 割れた順に順位を表示する

---

## 設計方針（重要）

> **子機はできるだけシンプルに、作り込みは親機側（Node-RED・ブラウザ）に寄せる。**

- 子機のコードは **3年生に配布** する。当日は時間がないので、ブロック単位で「何をしているか」を説明する程度にとどめる。
- 子機の役割は **「圧力を測って送るだけ」**。
  - ゲームロジック（しきい値、風船の大きさ、割れ判定、順位）は **子機に入れない**。
  - 理由: しきい値や膨らむ速さを、当日 **親機側だけで一括調整** できるようにするため。
- 3年生が書き換えてよい箇所は **2〜3か所** に絞る（例: 自分の名前、風船の色）。
- 子機のコードは初心者が読める書き方にする。**コメントは日本語**で、ブロックごとに役割を書く。

## システム構成

```
子機 CoreS3 ×10 ──(Wi-Fi)──> MQTTブローカー ──> Node-RED ──(WebSocket)──> ブラウザ表示（プロジェクター）
```

### 通信方式: Wi-Fi + MQTT

- 経路: 子機 → Wi-Fi → MQTTブローカー → Node-RED
- 必要なもの:
  - 専用 Wi-Fi ルーター（**2.4GHz**）
  - MQTT ブローカー（Mosquitto または Node-RED 内の aedes）
- 大学の Wi-Fi（eduroam 等）は使わない。
- SSID・パスワード等は `secrets.h` に分離する（[開発ルール](#開発ルール)参照）。
- トピック:
  - 子機は `handson/balloon/<id>` に送信する
  - Node-RED は `handson/balloon/+` で購読する

### データ形式

- 子機が送る値: **ID（名前）** と **ゼロ点からの圧力差**（＋必要なら色）
- 送信頻度: **1秒に10〜20回** 程度
- ペイロードは JSON:
  ```json
  {"id":"ikai","p":3.2}
  ```
- Node-RED → ブラウザは、全員分をまとめて 1秒に10〜20回程度に間引いて送る。

### 表示（ブラウザ）

- Node-RED Dashboard は使わず、`http in` ノードで配信する **自作HTML** ＋ `websocket out` で描画する（風船の演出の自由度のため）。
- 作り込み候補:
  - 接続待ち画面（接続済みの子機一覧）
  - 3・2・1 カウントダウン
  - 10人分の風船のリアルタイム表示
  - 割れる演出、順位表
  - 複数ラウンド制
  - 通信が途切れた子機の表示

## ハードウェア

### M5Stack CoreS3

| 項目 | 値 |
|---|---|
| PlatformIO board | `m5stack-cores3` |
| framework | `arduino` |
| ライブラリ | `m5stack/M5Unified` |
| シリアル速度 | `monitor_speed = 115200`（コード内の `Serial.begin()` と **必ず合わせる**） |
| USB | ESP32-S3 内蔵USB（USB CDC）で接続するため、通常は **ドライバ不要** |

### Unit Tube Pressure（チューブ型空気圧センサユニット, SKU: U130）

| 項目 | 値 |
|---|---|
| センサー | MCP-H10-B200KPPN |
| 測定範囲 | -100〜200 kPa（ゲージ圧） |
| 出力 | 0.1〜3.1 V のリニア出力、精度 ±1.5 kPa |
| 電源・接続 | 5V、**PORT.B** に接続。HY2.0-4P の **白線がアナログ出力**（黄線は NC） |
| 換算式 | `P[kPa] = 100 * Vout[V] - 110` |
| 無圧時の出力 | 約 1.1 V |

**読み取りの方針**

- 人が吹く圧力は数〜十数 kPa 程度で、測定範囲のごく一部しか使わない。そのため:
  - **起動時に無圧の値を平均してゼロ点にし、差分を使う**
  - 読み取りは複数回の平均でノイズを抑える
  - 吹いていないのに膨らまないよう、**不感帯（しきい値）は親機側で設ける**

> ⚠️ 実際に吹いたときの値の変化量・ノイズは **実機で未確認**。1個で検証してから10個購入する予定。

## 開発ルール

- **`main` は常に動く状態に保つ。** 作業はブランチ（例: `feature/child-sensor`）で行い、**PR 経由でマージ** する。
- **秘密情報はコミットしない。** `secrets.h` / `flows_cred.json` は `.gitignore` に入れ、代わりに `secrets.example.h` を置く。
- `.pio/` はビルド成果物なのでコミットしない。
  - ※ `.gitignore` は PlatformIO プロジェクト作成時に整備する。
- Node-RED のフローは `flows.json` を書き出してコミットする。**同時編集は衝突しやすいので避ける**（担当を1人に決める）。
- 3年生が詰まったときに追いつけるよう、**ステップごとの完成コード** を用意する（フォルダまたはタグ: `step1-hello`, `step2-display` …）。

## ハンズオンのタイムテーブル（目安）

| 時間 | 内容 | 到達点 |
|---|---|---|
| 0:00〜0:10 | 導入・完成形デモ | ゴールがわかる |
| 0:10〜0:35 | PlatformIO の使い方 | シリアルに「Hello」が出る |
| 0:35〜0:55 | 画面表示（M5Unified 導入） | 画面に名前が出る |
| 0:55〜1:15 | ボタン・タッチ入力 | タッチで反応する |
| 1:15〜1:25 | 休憩（遅れた人の追いつき） | |
| 1:25〜1:55 | センサーを読む（圧力ユニット） | 圧力が画面に出る |
| 1:55〜2:35 | 通信 | 自分のデータが送れた |
| 2:35〜3:05 | 全員でつなげて風船ゲーム | 大画面に全員の風船が出る |
| 3:05〜3:20 | まとめ・研究紹介 | |

PlatformIO のパートでは次の2つに絞って教える:

1. ステータスバーの4つのボタン（ビルド・書き込み・シリアルモニタ・クリーン）
2. `platformio.ini`

## トラブル集（`docs/` に反映予定）

| 症状 | 確認すること |
|---|---|
| 書き込み時にポートが見つからない | 充電専用ケーブルでないか／リセットボタン長押しでダウンロードモード／USBハブの電力不足 |
| シリアルモニタに何も出ない | `monitor_speed` の不一致、USB CDC 設定 |
| 書き込みが失敗する | シリアルモニタを閉じてから再実行 |
| 吹いても値が上がらない | チューブの抜け・ゆるみ |
| Wi-Fi につながらない | 2.4GHz か、SSID/パスワード |
