# node-red

Node-RED のフロー（`flows.json`）を置きます。

- MQTT で `handson/balloon/+` を購読し、ゲームの判定（膨らみ・割れ判定・順位）をすべてここで行います。
- 全員分の状態（`state`）を WebSocket `/ws/balloon` でブラウザへ 1秒に約20回送ります。
- 表示画面（`web/`）を `/balloon/` で配信します。
- 同時編集は衝突しやすいので、担当は1人に決めます。
- `flows_cred.json` はコミットしません。

メッセージ形式・ゲームのルールはリポジトリ直下の README を参照してください。

## 事前準備

MQTT ブローカーは、Node-RED の中で動く **aedes**（`node-red-contrib-aedes`）を使います。Mosquitto などを別に入れる必要はありません。
初回だけ `~/.node-red` にインストールしてください（エディタの「パレットの管理」から入れても同じです）。

```bash
cd ~/.node-red
npm install node-red-contrib-aedes
```

## 動かし方

**リポジトリ直下（`web/` と `node-red/` があるフォルダ）** に移動し、`web/` の場所を環境変数 `BALLOON_WEB_DIR` に入れてから、この `flows.json` を指定して起動します。
（`$PWD` = 今いるフォルダを基準にしているので、別のフォルダで実行すると `web/` が見つかりません）

```powershell
# PowerShell
cd <リポジトリの場所>\handson-2026-m5
$env:BALLOON_WEB_DIR = "$PWD\web"
node-red "$PWD\node-red\flows.json"
```

```bash
# macOS / Linux
cd <リポジトリの場所>/handson-2026-m5
BALLOON_WEB_DIR="$PWD/web" node-red "$PWD/node-red/flows.json"
```

- どこからでも起動したいときは、`$PWD` の部分を絶対パスに書き換えてください。
- 設定やインストール済みのノードは、ふだんどおり `~/.node-red` のものが使われます（フローのファイルだけがリポジトリの `flows.json` になります）。

- http://localhost:1880/balloon/ を開き、右上が「接続済み」になれば OK です。
- エディタ（http://localhost:1880/）でデプロイすると、この `flows.json` が直接書き換わります。そのままコミットしてください。
- 1880 番が使用中のときは `-p 1881` のようにポートを変えられます。

## フローの中身

タブ「風船ゲーム」に、次の4つのまとまりがあります。

| まとまり | 内容 |
|---|---|
| ① ゲームの設定 | 不感帯・しきい値・制限時間など。「ゲーム設定」ノードの JSON を書き換えてデプロイすると反映される |
| ② 子機のデータを受け取る | MQTT ブローカー（aedes, ポート 1883）で子機のデータを受け取り、膨らみを足し込み、割れ判定・順位付けをする |
| ③ ゲームの進行・ブラウザとのやりとり | 0.05秒ごとに段階（カウントダウン → 計測 → 終了）を進めて `state` を送る。スタート・リセットを受け付ける |
| ④ 表示画面の配信 | `/balloon/` で `web/` のファイルを返す |

### ゲームの設定（当日調整するパラメータ）

| キー | 内容 | 今の値 |
|---|---|---|
| `deadzone` | 不感帯 [kPa] | 0.5（仮） |
| `threshold` | しきい値 [kPa·秒] | 30（仮） |
| `timeLimit` | 制限時間 [秒] | 60（仮） |
| `maxRank` | 何位まで決まったら終了するか | 5 |
| `countdownFrom` | カウントダウンの開始値 | 3 |
| `offlineMs` | この時間 [ミリ秒] データが来なければ通信切れ | 2000 |
| `maxPlayers` | 参加できる最大人数 | 10 |

- ゲームは、**5位まで決まる・全員割れる・制限時間になる** のどれかで終了します。
- 「参加者の一覧を消す」ノードのボタンを押すと、参加者を空にして待機に戻します（子機の名前を変えた人の古いマスが残ったときなど）。

### 子機（実機）をつなぐ

1. この PC と子機を、同じ Wi-Fi ルーター（2.4GHz）につなぐ
2. この PC の IP アドレスを調べる（Windows: `ipconfig` の「IPv4 アドレス」）
3. 子機の `child/include/secrets.h` に SSID・パスワードと、`MQTT_HOST` にその IP アドレスを書いて書き込む
4. 子機の画面の下が `Wi-Fi ○  MQTT ○` になり、表示画面に自分のマスが出れば OK

- 初めて起動したときに Windows ファイアウォールの確認が出たら、**プライベートネットワーク** で許可する（1883 番を子機から受けるため）。
- `MQTT ×` のままなら、`MQTT_HOST` の IP・ファイアウォール・PC と子機が同じルーターにいるかを確認する。

### モック（ダミーの子機）

子機がないときに画面を確かめるための **モック** です。有効にすると、子機の代わりに `{"id":"ikai","p":3.2}` を流します（7人分・1人あたり1秒に10〜20回・最後の1人は30秒ごとに3秒間通信が途切れる）。

- 初期状態では **無効** です。使うときは「モック 0.05秒ごと」ノードを **有効** にしてデプロイします。
- 実機と同時に使うとマスが混ざるので、実機をつなぐときは無効に戻します。
