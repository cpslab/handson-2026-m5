## トラブル集

### 書き込み・シリアルモニタ

| 症状 | 確認すること |
|---|---|
| 書き込み時にポートが見つからない | 充電専用ケーブルでないか／リセットボタン長押しでダウンロードモード／USBハブの電力不足 |
| シリアルモニタに何も出ない | `monitor_speed` の不一致、USB CDC 設定 |
| 書き込みが失敗する | シリアルモニタを閉じてから再実行 |
| 書き換えたのに動きが変わらない | ファイルを**保存してから**書き込んだか（タブに ● が付いていたら未保存） |

### センサー

| 症状 | 確認すること |
|---|---|
| 吹いても値が上がらない | チューブの抜け・ゆるみ／PORT.B につないでいるか |

### Wi-Fi・MQTT（子機の画面の下の `Wi-Fi ○  MQTT ○`）

| 症状 | 確認すること |
|---|---|
| 「Wi-Fi 接続中...」から進まない | `secrets.h` を**保存してから**書き込んだか／`secrets.example.h` ではなく `secrets.h` を書き換えたか／2.4GHz の Wi-Fi か／SSID・パスワード（大文字・小文字も区別される） |
| `Wi-Fi ○` なのに `MQTT ×` のまま | `MQTT_HOST` が正しい IP アドレスか（下の「PC の IP アドレスの調べ方」）／Node-RED が起動しているか／Windows ファイアウォールで Node.js を許可したか／ルーターが機器どうしの通信を止めていないか（下の「切り分け」） |
| `MQTT` が**ときどき** `×` になる（すぐ `○` に戻る） | Node-RED でデプロイした直後なら正常（ブローカーも起動し直すため）／それ以外なら、シリアルモニタの「MQTT につなぎ直します（理由 ○）」の数字を見る（`-4` 応答がなく時間切れ・`-3` 接続が切れた）／PC がスリープや省電力になっていないか |

#### PC の IP アドレスの調べ方

PowerShell で `ipconfig` を実行し、**「Wireless LAN adapter Wi-Fi」** の「IPv4 アドレス」を使う。

- `ipconfig` には IPv4 アドレスがいくつも出ることがある。**WSL（vEthernet）・Tailscale・VPN などのアドレスは使わない。**
- WSL のアドレス（例: `192.168.0.1`）は `secrets.example.h` のひな形（`192.168.0.10`）と似ているので、取り違えやすい。
- Wi-Fi をつなぎ直す・テザリングに変えるなどすると IP が変わる。変わったら `MQTT_HOST` を書き換えて書き込み直す。

#### 切り分け（PC 側か、ネットワーク側か）

スマホを子機と同じ Wi-Fi につなぎ、ブラウザで `http://<PC の IP>:1880/balloon/` を開く。

- **開いた** → PC とネットワークは問題ない。`MQTT_HOST` の値と、子機側を確認する。
- **開かない** → ファイアウォールか、ルーターが機器どうしの通信を止めている（AP 分離）。専用ルーターに変えるか、ルーターの設定を確認する。

### Node-RED

| 症状 | 確認すること |
|---|---|
| 起動すると `Error: port in use` | 前に起動した Node-RED が残っていないか（その画面で `Ctrl + C`）。見つからなければタスクマネージャーで `node.exe` を終了する |
| 表示画面が開かない | `/balloon/`（末尾の `/` あり）で開いているか／`BALLOON_WEB_DIR` を設定してから起動したか（[node-red/README.md](../node-red/README.md)） |
